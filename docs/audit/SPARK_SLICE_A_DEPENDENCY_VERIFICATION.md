## 2. Contradictions/corrections to the preliminary map

1. **`[unity].[LogEvents]`** - The preliminary map states "no EF entity or query service exists". However, the `ConsoleHost` configuration shows that Serilog is configured to write to a SQL sink named `LogEvents` in the `unity` schema. This indicates that while there's no EF mapping, the table exists and is populated via Serilog. The audit will need to either:
   - Use a raw SQL query against the `unity.LogEvents` table
   - Or implement a read-only EF mapping for this table if the audit needs to access it directly

2. **`PolicyID sanitization/filter`** - The preliminary map correctly notes that no matching implementation was found in the repository. The compatibility implementation is properly identified as a temporary measure.

3. **`event persistence`** - The preliminary map correctly identifies that `UnityEvents` is available through `SaveUnityEventAsync`, but the metadata is stored as `Dictionary<string,string>`. This is confirmed in the `PolicyDbContext.cs` file lines 107-110 and 132-135.

## 3. Implementation blockers

1. **`[unity].[LogEvents]` table access** - The audit SQL requires querying `LogEvents` for timestamp-based filtering. While the table exists and is populated by Serilog, there's no EF mapping or query service for it. This blocks the implementation of the log analysis portion of the audit.

2. **Kafka producer identification** - The preliminary map correctly identifies that the Kafka producer is a placeholder. The actual Kafka producer contract and transport mechanism must be identified before implementing the audit event delivery.

3. **CA_EPV_REPORTING EF mapping** - While the schema is known, the EF mapping for `CA_EPV_REPORTING` needs to be added to `PolicyDbContext.cs`. This is a blocker for accessing the CA data source.

## 4. Questions requiring Larry's decision

1. **LogEvents access method**: Should the audit use a raw SQL query against the `unity.LogEvents` table or implement a read-only EF mapping for this table? The current Serilog configuration uses this table, but the audit needs to query it.

2. **Kafka producer contract**: What is the approved Kafka producer/transport contract for audit events? The current implementation uses `ImmediateUnityPublisher` which logs and writes to `UnityEvents`, but the audit needs to publish to Kafka.

3. **CA_EPV_REPORTING EF mapping scope**: Should the EF mapping for `CA_EPV_REPORTING` include only `PolicyID` and `CAFDeletionDate` as specified, or should additional fields be included based on future audit requirements?

4. **Executable SQL evidence storage**: How should the complete executable SQL evidence be stored and retrieved? The audit needs to store the SQL statement along with its parameters for verification purposes.
