## Existing event limitations

`EventBus.Metadata` is stored as `Dictionary<string,string>`. The requested audit event is nested, potentially large, and includes executable SQL. Flattening it into this dictionary would lose structure or force one opaque JSON string. A dedicated versioned audit envelope is required at the publisher boundary, but its transport and storage must follow the approved Kafka integration rather than an invented producer.

## Behavioral parity requirements

For the same completed execution, the original SQL and application implementation must agree on:

- Policies in `CA_EPV_REPORTING`
- total excluded
- total processed
- `NO_DRIFT`, `DRIFT`, and `MISSING_BASELINE`
- PDE-only diagnostic count
- every excluded PolicyID
- every final exclusion reason

Aggregate-only agreement is insufficient.

## Original implementation gates and current disposition

The bounded implementation resolved or isolated these gates as follows:

1. `LogEvents`: a narrow read-only EF projection over the existing Serilog table.
2. Kafka: no producer exists, so delivery remains behind `IPolicyDriftAuditPublisher`; current status is explicitly persisted-not-sent.
3. SQL evidence: embedded complete SQL artifact, SHA-256, and parameters stored with the envelope.
4. Live parity: still requires an authorized completed execution and remains a production-validation gate.

## Confirmed `CA_EPV_REPORTING` behavior

The source population is every distinct non-null PolicyID except the literal string `null`. The excluded population is that set minus PolicyIDs represented by `PolicyDriftEval` rows whose `ExecutionId` begins with the current execution ID.

Deletion state must be calculated across every CA row for a PolicyID:

- `NO`: every row has `CAFDeletionDate == null`.
- `YES`: every row has `CAFDeletionDate != null`.
- `YES+`: the group contains both deleted and non-deleted rows.

Do not reduce this to `Any(CAFDeletionDate != null)` because that loses `YES+`.

## Confirmed compatibility filter

Until the authoritative production PolicyID function is supplied, the audit may execute an isolated compatibility implementation that preserves only ASCII letters, digits, and hyphen. It must be explicitly marked as a merge-integration stub, not a new authoritative business rule. The classification contract and Kafka schema must not change when the implementation is replaced.
